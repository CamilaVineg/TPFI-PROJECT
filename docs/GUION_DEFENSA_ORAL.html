1. Introducción Inicial (30 segundos)

Qué decir al tribunal: "Buenas tardes profesores. Nuestro proyecto es una aplicación distribuida cliente-servidor desarrollada sobre TCP y conectada a AWS DynamoDB.
El sistema implementa cuatro patrones de diseño GoF:
1. Singleton: para gestionar el acceso físico único a las tablas CorporateData y CorporateLog.
2. Proxy: para interceptar, validar datos mínimos y proteger las claves primarias antes de acceder a la base.
3. Observer: para notificar en tiempo real a clientes suscriptos cada vez que un registro cambia.
4. Iterator: para recorrer y paginar transparentemente DynamoDB sin truncamientos ni saturación de memoria.
A continuación, realizaremos la demostración funcional en vivo con 3 servicios concurrentes."

2. Puesta en Marcha de Servicios (1 minuto)

Paso 2.1: Iniciar el Servidor de Aplicaciones (Terminal 1)
python -m tpfi.singletonproxyobserver -p 8080 -v
Qué decir: "Iniciamos en la Terminal 1 el servidor multihilo en el puerto 8080. Como pueden observar en los logs, los repositorios se inicializan bajo el patrón Singleton: una única instancia para todo el proceso. Cada cliente entrante será atendido en un hilo independiente para garantizar concurrencia."
Paso 2.2: Conectar el Observador Reactivo (Terminal 2)
python -m tpfi.observerclient -s 127.0.0.1 -p 8080 -v
Qué decir: "En la Terminal 2 conectamos el ObserverClient. El observador envía su UUID de CPU solicitando la suscripción. El servidor confirma con status: ok y deja el socket TCP abierto en estado de escucha activa para recibir notificaciones push."

Qué decir: "Enviamos una petición donde el cliente intenta modificar el campo reservado id (clave primaria). Como ven, el Proxy interceptó el requerimiento y lo rechazó con status: error. La petición ni siquiera llegó a la base física, protegiendo la integridad de la base de datos."

5. Respuestas Rápidas para Preguntas del Tribunal

  • ¿Por qué session_id lo crea el servidor y no el cliente?
    Respuesta: "Por seguridad y no repudio. Si el cliente lo eligiera, podría sobrescribir auditorías anteriores o falsear identidades en CorporateLog."
  • ¿Qué pasa si se cae el observador?
    Respuesta: "El servidor detecta el socket roto, hace una poda automática (unsubscribe) para no dejar descriptores zombis, y el cliente tiene un bucle que reintenta reconectarse cada 30 segundos."
  • ¿Por qué usan delimitador \n en los sockets?
    Respuesta: "Porque TCP es un flujo continuo de bytes (stream). Sin encuadre por delimitador, los mensajes podrían mezclarse o fragmentarse. JsonSocket bufferiza y entrega mensajes JSON completos."
  • ¿Qué pasa si falla Internet en el aula?
    Respuesta: "Tenemos preparado el script python demo_runner.py que emula el ciclo completo contra repositorios en memoria de forma 100% offline."
